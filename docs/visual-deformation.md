# Мягкая визуальная деформация

Настройка находится в **Расчёт → Рисование → Деформация**: «Выкл», «Ускорение», «Прилив».

По уточнению пользователя уменьшен яйцеобразный вид объектов. Изменены только параметры отображения; расчётные тела и контакты остаются сферическими.

| Параметр | Новое поведение |
|---|---|
| Максимальное отношение осей | 1.08 вместо 1.30: разница до 8% вместо 30% |
| Ракурс | Сплющивание ослабевает как sin² угла между осью деформации и взглядом; вдоль оси — круг |
| Плавность | Экспоненциальное сглаживание силы и направления с постоянной времени 0.18 с; при обычной частоте кадров около 0.5 с до 95% изменения |
| Направление оси | Противоположные векторы считаются одной осью, чтобы не поворачивать силуэт на 180° |
| Режим «Прилив» | Мягкое насыщение: `u/(4+u)`, где `u = угловой размер источника / 0.016`; на прежнем пороге максимума теперь 20% интенсивности, то есть до 1.6% разницы осей |
| Основная сцена и PiP | Одно сглаженное состояние на тело, отдельная проекция для каждой камеры |
| Java2D и OpenGL | Одинаковые параметры формы; площадь отображаемого эллипса сохраняется |

Состояние обновляется один раз за кадр и очищается при переключении режима. Отключение деформации возвращает обычные круги. Удалённые тела не остаются в кеше. Выбор массивных источников для прилива выполняется один раз за кадр.

## Проверка

`VisualDeformationTest` проверяет ограничение осей, площадь, ракурсы сбоку/45°/вдоль оси, плавность включения и изменения направления, разворот знака оси, независимость проекций основной камеры и PiP, мягкую приливную чувствительность и отсутствие изменений координат физических тел.

Сравнение через реальные функции Java2D и OpenGL сохраняется в **`build/deformation-preview.png`**: старый максимум, новый максимум сбоку, ракурс 45° и взгляд вдоль оси. Это программный рендер обоими путями, а не ручная проверка всех сцен приложения.

Проверки в текущем прогоне: `VisualDeformationTest` — 138, `GlSceneTest` — 12, `CloudTest` — 14; все прошли. В полном `build-tests.ps1` проверка деформации выполняется вместе с проверками рендера.

Если основной JAR занят работающим приложением, новая версия находится в `build/input/universal-interaction-formula-fixed.jar`. После закрытия старого окна можно запустить `build/run-fixed.bat`: он скопирует подготовленную версию на основной путь и запустит её. Если основной файл всё ещё занят, скрипт запускает отдельную подготовленную сборку.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-tests.ps1
```
