# Модель W = Q·N в 3D — Java-версия

Java-перенос проекта `universal-interaction-formula-master` (`h2-3d.html`, коммит `6fb0b29`). Физика, формулы и порядок вычислений те же; интерфейс — Swing. HTML-файл из этой копии убран, он остался в истории git.

## Сборка и запуск

Нужен JDK 22 или новее (для вызова видеокарты через Foreign Function & Memory API). `build.ps1` ищет его сам: `JAVA_HOME`, затем `javac` из `PATH`, затем `C:\Program Files\Java\jdk-*`; найденный путь записывается в `build/jdk.txt`, и `run.bat` запускает окно тем же JDK. `JAVA_HOME` не меняется. Maven, Gradle и JCuda не нужны.

```bat
build.bat
```

`build.bat` компилирует `src/main/java` и `src/test/java` (`--release 22`), запускает тесты `uif.FormulaTest` и собирает `build/input/universal-interaction-formula.jar`.

```bat
run.bat
```

`run.bat` собирает проект, если JAR ещё нет, и открывает окно.

Снимок окна без ручного запуска (для проверки интерфейса):

```bat
java -cp build/classes uif.ui.SnapshotTool build/snap.png atoms 6
```

Режимы снимка: `atoms`, `details` (раскрыта формула), `sandbox`, `chamber` (песочница с замкнутой областью), `big:N` (песочница из N тел, печатает время кадра; `-Dfield=false` — без облака поля). `-Dshaders=false` — рисовать Java2D вместо шейдеров, `-Dclouds=true` — частицы облаками своего поля (как кнопка «поле» в теме «Вид»). Для `big:N` и вызова видеокарты добавьте `--enable-native-access=ALL-UNNAMED`. Снимок делается после прогона заданного числа секунд при «демо» G.

## 1. Формула

`W = Q·N_w` (Катющик; монография, стр. 32–34; «Формула мироздания», 14:27):

- `W` — воздействие;
- `Q` — качественный показатель воздействия: `Q = k_a·C1/(4πR²)`, где `k_a = 1`, `C1` — интенсивность базового воздействия, `R` — расстояние до источника;
- `N_w` — количественный показатель (заряд): `N_w = V·q = h·S·q`; для сферы `S = πr²`, `h = 4r/3`, `V = hS = (4/3)πr³`; для тяготения заряд — масса;
- `F = f(α)·n_f·W`, `n_f = k_v·hSq = m`; для тяготения `k_v = 1`, `f(α) = 1`, откуда `F = C1·m1·m2/(4πR²) = G·m1·m2/R²`.

В коде всё взаимодействие идёт через одну функцию `QN(r, R, N_j) = Q(r)·N_j`, где `Q(r) = k_a·C1/(4πr²)` и `C1 = 4πG`:

- `W_i = Σ_j Q_j·N_j` — вектор на источник;
- `F_i = f(α)·n_f·W_i`, `n_f = k_v·N_i`;
- `a_i = F_i/m_i`, где `m_i = k_v·N_i`.

Константы `k_a`, `k_v`, `f(α)` в коде явные (`K_A`, `K_V`, `F_ALPHA`) и равны 1.

Внутри шара источника действует только та часть заряда, что попала внутрь: `N(r) = V(r)·q = N·(r/R)³` — это та же `N = Vq`, а не обрезка `r`. Для пары берётся `R = max(rad_i, rad_j)`, поэтому действие равно противодействию.

**Непроницаемые тела** (переключатель «Вид» → «стенка» → «непроницаемые»; по умолчанию выключен). Добавка модели: **мягкая оболочка** — отталкивание включается на `R_i+R_j+δ` (`δ = 25 %` суммы радиусов) и плавно растёт от нуля, поэтому жёсткой границы нет и тела «сталкиваются полями», а не поверхностью. Сила `μ·ω²·s` (`s` — глубина в оболочке, `μ` — приведённая масса, `ω = 30` рад/с) с вязким слагаемым `−2λ·v_r` (`λ = 6` 1/с): удар гасится, отскок теряет ~70 % скорости, импульс пары сохраняется точно. Потенциальная `½μω²s²` входит в `energy()`, потери видны в `ΔE/E`.

Из той же формулы получаются:

- **энергия:** `U = −kQ·N_i·N_j·φ(r)`, где `φ = 1/r` снаружи и `(3R² − r²)/(2R³)` внутри; `−dU/dr` совпадает с силой;
- **начальные скорости:** круговая орбита из `a = Q(r)·(N_b·N_g/m_b + N_g·N_b/m_g) = v²/r`, импульс делится между телом и центром;
- **шаг интегрирования:** `dt = min(1/120, 0.02·√(r³/(kQ·(N_i+N_j))))` по самой тесной паре;
- **свечение поля (G):** `Q_j·N_j`, отнесённое к полю протона на `r0`.

В модели нет кулона, кора `kField`, БГП, демпферов, сил `cRes`/`kDef` и затенения `occ`.

### Виды атомов

Список «атом» в теме «Частицы»: водород-1 (`p e`), водород-2 / дейтерий (`p n e`, по умолчанию), водород-3 / тритий (`p 2n e`), гелий-4 (`2p 2n 2e`), литий-7 (`3p 4n 3e`). Выбор только задаёт вид для следующих «+ атом» — сцену не сбрасывает. Сборка (`World.makeAtom`): первый протон в покое, остальные нуклоны (p и n по очереди) — на круговых орбитах вокруг уже собранного ядра на `rn·(1 + 0.35k)`, электроны — по одному на круговых орбитах вокруг ядра и внутренних электронов на `r0·(1 + 0.6k)`. Оболочек нет, ядро держит только тяготение — тяжёлые ядра в модели неустойчивы. Для дейтерия сборка совпадает с прежней.

### Тяготение: прямое и комплексное (КУО)

Переключатель «Тяготение» в панели; при запуске и после «перезагрузить» — комплексное (КУО).

- **Прямое** — версия Ньютона: тела притягиваются по `W = Q·N`. Автор монографии считает её физически невозможной (стр. 20–21, 29) — в модели она оставлена для сравнения.
- **Комплексное (КУО)** — версия комплексного отталкивания (монография, стр. 15–17, 26–28, 35–40). Все тела отталкивают друг друга, и удалённые массы — комплекс удалённых объектов — тоже отталкивают каждое тело. Однородный КУО со всех сторон даёт ноль («сфера с равномерным распределением даёт ноль суммарного воздействия», стр. 17). Тело `j` рядом с телом `i` «вырезано» из КУО в своём телесном угле: на той стороне в комплексе разряженная область — дефицит массы, в точности равный массе `j` (масса сохраняется, стр. 37). Отталкивание от КУО с противоположной стороны больше — тело `i` приталкивается к `j`, сила направлена «извне — от комплекса к пробному телу» (стр. 40).

В коде (`Kuo`) две шкалы: для пары `i–j` частное отталкивание тел `−β_т·W_ij` (от `j`) и приталкивание от дефицита массы КУО `+β_к·W_ij` (к `j`); итог — `(β_к − β_т)·W_ij` к `j`. По умолчанию шкалы связаны, `β_к = 1 + β_т`, и итог ровно `W_ij`. Дефицит пропорционален массе и складывается по телам (два тела в одном телесном угле дают дефицит, равный сумме масс), поэтому численно комплексное тяготение совпадает с прямым — как и утверждает автор («в силу эквивалентности формульного выражения», стр. 40). Различаются составляющие и их направление; их показывают стрелки «силы». Шкалы в монографии не заданы — свободные параметры (два логарифмических ползунка, 0…10¹⁵; дальше в double `1 + β` неотличимо от `β`).

**Замкнутый КУО** (переключатель «КУО: бесконечный / замкнутый» в той же теме; по умолчанию — бесконечный, как в монографии). Добавка модели: у комплекса конечный запас `N_КУО`, и локальные массы его расходуют — `q = ΣN/N_КУО`, приталкивание ослабляется до `β_к·(1 − q)·W`, итог пары `(β_к·(1 − q) − β_т)·W`. При `q = 1 − β_т/β_к` итог обращается в ноль — равновесие, как в закрытой камере; при большем `q` тела расталкиваются, то есть локальная масса не может превысить запас. `N_КУО → ∞` возвращает прежнюю модель (проверка 32 в `FormulaTest`). Ползунок запаса — `10²…10¹²`, значение `q` и итог пары показаны под ним.

- **Связанные шкалы** (по умолчанию, кнопка «связать: β_к = 1 + β_т»): итог считается при `β = 0` — без вычитания огромных составляющих, поэтому при любом `β_т` он до бита тот же, что в W = Q·N. Составляющие для стрелок — `rep = rep₀ − β_т·S`, `push = push₀ + β_т·S` (расчёт линеен по `β`, `S` — сумма `W_ij` по парам не из одного диполя), только когда стрелки нужны.
- **Развязанные** (сдвинут ползунок `β_к`): итог `g·W`, `g = β_к − β_т`: `g > 1` — тяготение сильнее, `g < 0` — тела расталкиваются. Это уже не W = Q·N, а проверка «что если». Потенциал пар тоже `×g`, поэтому энергия и импульс сохраняются (тест 16). Полюса одного диполя держит их собственная связь — шкалы её не меняют. Шаг выбирается по `dynTime/√g` при `g > 1`; «весь шаг на видеокарте» в этом случае не используется — силы считаются через `split`.

Механизм с потоком сквозь тела и экранированием (поглощение, непрозрачность, насыщение, перекрытие) — это модель Лесажа–Фатио, которую автор отвергает (стр. 57–58); в модели его нет.

### Соответствие источникам

- `W = Q·N` — совпадает.
- `Q = k_a·C1/(4πR²)` — совпадает буквально; `C1 = 4πG`.
- `N = Vq = hSq` — в коде `V`, `q`, `h`, `S` явные, `N = V·q`, и масса `m = k_v·N`. Изменение `q` меняет и массу, и заряд.
- `F = f(α)·n_f·W` — совпадает; `n_f = k_v·N_i`.
- Кулон в монографии и в доступных фрагментах фильма не упоминается: заряд — только общий количественный показатель, для тяготения — масса.

### Дискретное и непрерывное

Модель следует разбиению «частицы + поле»: частицы дискретны, поле непрерывно. Каждое тело — однородная сфера: снаружи поле `1/r²`, как у точечного источника, внутри — `∝ r`.

### Только доказанные частицы

В модели только частицы, доказанные напрямую и с измеренной массой: протон (Резерфорд, 1919), нейтрон (Чедвик, 1932), электрон (Томсон, 1897). Каждая — одно однородное тело.

Кварков и «массы связи» нет, хотя они были в промежуточной версии:

- кварки доказаны только косвенно (рассеяние на протонах, SLAC 1968–69), свободными их никогда не наблюдали;
- их массы (токовые 2.16 / 4.67 МэВ, конституентные ~312 МэВ) — вычисленные или модельные параметры, а не измерения;
- «масса связи» вообще не частица.

В коде нуклон — тело с тегами `nuc` и `nk` (`p`/`n`), с ним работают как с группой (`orbit`, удаление, центр масс).

### Способ добавления частиц

Переключатель «способ» (тема «Частицы», «Как добавлять») для кнопок «+» p, n, e, атом, диполь — `World.spawn`:

- **орбита** (по умолчанию) — круговая орбита вокруг всех имеющихся тел как одного, скорость из W = Q·N;
- **покой** — на том же расстоянии, скорость 0;
- **бросок** — скорость `throwK` × круговая к центру масс тел, отклонённая прицелом `throwAim` (0 — в центр, 1 — 45° мимо).

Всё — в `World.launch` (обобщённый `orbit`); суммарный импульс сохраняется (тест 27). След пишется по модельному времени (`Formula.TRAIL_DT`), а не по шагам — иначе у жёсткого диполя он умещался бы в доли секунды.

### Диполь (добавка модели, гипотетическая частица)

Единственное честно отмеченное исключение из правила «только измеренные частицы»: **неделимый заряд-диполь** из полюсов `d+` и `d−` (кнопка «+» в строке «диполь»). Полюса неравные: N₊ = 0.002, N₋ = 0.001 — меньше электрона; радиус из N = V·q.

- **Суммарный заряд** N₊ − N₋ = 0.001: издали диполь — тело с этим зарядом и массой N₊ + N₋. Он притягивается целиком, притягивает других и добавляется на круговую орбиту (`World.lump` считает N со знаком, поэтому `orbit` и `pair` работают для диполя как для одного тела). При N₋ ≥ N₊ диполь целиком отталкивается и ставится в покое.

- **Знак.** У тел есть знак `Body.sign` (+1 у p, n, e, d+; −1 у d−). Сила пары W = Q·N умножается на sᵢ·sⱼ: одинаковые знаки притягиваются, разные отталкиваются. У прежних тел всё по-старому.
- **Почему держится — без связки.** Полюса отталкивают друг друга (`−f(α)·QN(r, R)`) и экранируют друг друга от КУО — прижатие `+f(α)·χ·QN(r, R_s)` с радиусом экранирования R_s = L·χ^{1/3}. Вдали прижатие в χ раз сильнее → стягиваются; внутри R_s оно слабеет ∝ r, а отталкивание растёт ∝ 1/r² → не слипаются. Равновесие r* = L устойчиво. Без оболочки R_s (экранирование только телом полюса) равновесия нет — прижатие у сближения растёт быстрее 1/r².
- **Неделимость честная:** разорвать можно только энергией больше энергии связи `World.bindingEnergy` (показывается в сводке). f(α) внутри диполя (по умолчанию 10⁶) делает связь жёстче, чтобы протон, тянущий d+ и толкающий d−, не разрывал диполь.
- Код: `World.pairQN` / `World.pairPhi` (сила и потенциал пары — для всех тел), `Kuo.compute` (составляющие), `World.addDipole` / `removeDipole`. Энергия и импульс сохраняются (тест 25: орбита диполя вокруг протона, ускорение по суммарному заряду, отталкивание при N₋ > N₊).

### Расчёт пар: процессор и видеокарта

Самая дорогая часть шага — перебор всех пар тел (N² / 2): силы `W = Q·N`, составляющие КУО, энергия, самая тесная пара для шага. Всё это — в `uif/Forces.java`. Координаты и свойства тел перед расчётом копируются подряд в массивы (`px, py, pz, N, rad, …`), а не читаются из объектов `Body`.

Четыре кнопки «считать на» (тема «Расчёт»): «авто», «CPU», «GPU double», «GPU float». Точные пути:

- **1 поток** — до `Forces.PAR_MIN = 64` тел (потоки дороже самого расчёта);
- **все ядра процессора** — от 64 тел (`ForkJoinPool`, тело `i` — одна задача);
- **видеокарта (CUDA, `double`)** — от `Forces.GPU_MIN = 1000` тел, если есть NVIDIA и драйвер. Ядро (`Gpu.SRC`) компилируется при запуске через NVRTC из `CUDA_PATH`; вызов — через `nvcuda.dll` без JCuda. Нет видеокарты или ошибка — расчёт сам возвращается на процессор, причина видна в панели.

«авто» выбирает путь по числу тел; «CPU» и «GPU double» — принудительно. **Результат во всех трёх точных путях совпадает до бита**, а не до 10⁻¹²: одинаковый порядок операций, только `sqrt` и деление по IEEE, умножение-сложение только явное (`Math.fma` ↔ `fma`, NVRTC с `--fmad=false`). Проверяет тест 28: ~2010 тел, силы, составляющие КУО, энергия, шаг — побитово.

На видеокарте — только перебор пар. Интегратор (Йошида), стенка области и сумма кинетической энергии — O(N), остаются на процессоре: пересылка координат и ответа — одна выгрузка и одна загрузка за вызов (~40 мкс), это меньше 1 % расчёта при 10 000 тел. Так у всех путей один и тот же код интегратора и стенки.

Время одного расчёта сил (i5-13400F, RTX 4070 SUPER, мкс):

| тел | 1 поток | 15 потоков | видеокарта |
|---|---|---|---|
| 100 | 63 | 38 | 122 |
| 1 000 | 4 954 | 943 | 876 |
| 3 000 | 72 675 | 7 408 | 2 784 |
| 10 000 | — | 78 390 | 19 418 |

Расчёт в `double` на игровой видеокарте медленнее, чем в `float` (у RTX 4070 SUPER `double` в 64 раза реже), поэтому выигрыш ×4, а не ×100.

#### Быстрый приближённый режим «GPU float»

Только по кнопке — «авто» его не выбирает. Ядро `Gpu.SRC_F`:

- формулы те же, во `float` (~7 верных знаков), `--use_fast_math`;
- `kQ` и `1/m` в ядро не входят: при честной G `kQ·N` меньше наименьшего `float`, поэтому множитель `f(α)·k_v·kQ·N_i/m_i` хост прикладывает в `double`;
- координаты — от средней точки сцены, чтобы разность близких тел не терялась;
- **пара полюсов одного диполя считается на хосте в `double`**: её сила — разность двух почти равных слагаемых, умноженная на f(α) = 10⁶, во `float` она теряется целиком (ошибка была до 10⁻³, стала ~10⁻⁷, как у всех);
- энергия для `ΔE/E` всегда считается в `double` (на видеокарте), поэтому сводка честно показывает потерю точности;
- пары тела `i` делят 8 потоков (блок 64 × 8, плитки в общей памяти): иначе при 10 000 тел занята только восьмая часть видеокарты.

Результат не до бита. Тест 28б: каждое ускорение и обе составляющие КУО совпадают с `double` до 10⁻⁴ (на деле наибольшая ошибка ~10⁻⁵, обычно ~2·10⁻⁷), `dynTime` — до 10⁻⁵, энергия — до бита.

#### Весь шаг на видеокарте

В «GPU float» шаг целиком идёт на видеокарте (`World.advanceGpu`, ядра `res_kd`, `uif_f`, `res_fin`, `res_min` в `Gpu.SRC_F`), с замкнутой областью тоже:

- координаты, скорости и ускорения живут на видеокарте в `double`; во `float` — только перебор пар;
- подшаг Йошиды — те же kick(h/2) · drift(h) · силы · kick(h/2), что в `World.substep`, три ядра на подшаг;
- пара полюсов диполя и множитель `kQ·N_i/m_i` — в `double` на видеокарте (`res_fin`);
- `dynTime` — наименьшее по телам на видеокарте; на процессор приходит одно число за шаг, по нему выбирается следующий шаг — как в `World.advance`;
- координаты тел скачиваются только для точки следа (первые 200 и все электроны), все координаты и скорости — один раз в конце кадра, обратно в тела. Вся остальная программа (сводка, камера, кнопки) видит тела как обычно;
- в КУО при связанных шкалах итог пары — тот же W = Q·N (−β·W + (1+β)·W), поэтому видеокарта считает его прямо, а составляющие для стрелок пересчитываются раз в кадр; при развязанных шагает процессор с силами на видеокарте;
- ошибка видеокарты — состояние тел не тронуто, расчёт переходит на процессор.

**Замкнутая область на видеокарте** — ядра `ch_kd`, `ch_wall`, `ch_nodes`, `ch_damp1…3` в том же порядке, что `World.substep`: kick · вязкий слой · drift · вязкий слой · силы · kick. Узлы, центр, потери и давление тел живут на видеокарте в `double` (массив `CH`), на процессор приходят в конце кадра:

- поле стенки на тела и реакция на узлы и центр — суммы по варпу и блоку, затем `atomicAdd`;
- узлы (пружина, натяжение соседей, внешнее давление) — одним блоком по 162 узлам;
- вязкий слой — неявная схема для всех тел сразу (см. «Вязкий слой у стенки»): тела складывают суммы для системы 3×3, один поток решает её, затем тела получают новые скорости. Порядок тел не влияет, поэтому видеокарта считает так же, как процессор.

Тест 28в: 505 тел, 462 шага. Шагов столько же, что в `double`, положения совпадают до 3·10⁻¹⁰, энергия сохраняется до 10⁻⁷, импульс — до 3·10⁻¹¹ от Σm|v|, следы — те же точки. Ещё проверяется КУО. Тест 28г — замкнутая область: 146 тел, часть у стенки летит наружу; положения, узлы, центр, потери и давление тел совпадают с `double`, `E + потери` и импульс тел вместе со стенкой сохраняются до ~10⁻¹⁰.

### Рисование шейдерами

Тела и следы по умолчанию рисует видеокарта: OpenGL 3.3 через FFM (`opengl32.dll`, без сторонних библиотек), класс `GlScene`. Кнопка «шейдеры» в теме «Расчёт» («Рисование») переключает на Java2D. Если OpenGL нет, рисует Java2D, а причина пишется в подсказке кнопки.

- Контекст живёт в скрытом окне «только для сообщений». Картинка рисуется во внеэкранный буфер с 4× сглаживанием (MSAA), читается в `int[]` и ложится в сцену одним `drawImage`: поверх пола, поля и стенки, под стрелки, подписи и сводку.
- **Тела** — круги-импостеры. Проекция и порядок «от дальних к ближним» считаются на процессоре в `double` (как `Camera.project`). Шейдер рисует то же, что `drawBodies`: свечение 1 → ½ → 0, ядро с бликом и тенью, дымку. Делает он это для всех тел, так что и при 10 000 тел у каждого есть свечение и объём. В Java2D от 400 тел остаются плоские диски.
- **Следы** проецирует сама видеокарта: точки идут относительно цели камеры, поворот и перспектива — те же, что в `Camera.project`. Глубина берётся как `w`, поэтому отрезок через ближнюю плоскость обрезается, а не пропадает. Яркость падает с возрастом точки плавно, без 24 ступеней.
- Тест `GlSceneTest` (в `build.ps1`) проверяет, что тело ложится в точку `Camera.project`, строки не перевёрнуты, ядро непрозрачное, а свечение полупрозрачное и гаснет к краю. Ещё он проверяет, что след ложится на проекцию своих точек и что отрезок за камерой обрезается.

### Частица как поле

Кнопка «поле» в строке «частицы» (тема «Вид») рисует частицу не шаром фиксированного размера, а тусклым широким ореолом её поля с яркой точкой-ядром в центре; «шар» возвращает прежний вид. Клавиши нет, в снимках — `-Dclouds=true`.

- **Ореол — поле `Q·N`.** Тянется до `CLOUD_CUT = 0.05` поля протона на `r0`: край `R = rc/√0.05 ≈ 4.5·rc`, где `rc = max(rad, r0·√(N/M_p))`. Яркость падает как `(1 − d/R)^2.4` и берёт `HALO_ALPHA = 0.25` яркости тела. Поэтому у протона ореол в `√1836 ≈ 43` раза больше по радиусу, чем у электрона.
- **Точка — ядро частицы.** Радиус `POINT_K = 2.5` радиуса тела, яркость `POINT_ALPHA = 0.85`, цвет — цвет тела, смешанный с белым на `POINT_WHITE = 0.15`. Точка мала, поэтому центр ярче границы: в «атомах» это звёздочки, а в плотной сцене — поле точек, а не заливка.
- **Яркость тела — из `Q·N`:** `a·(r1/rc)²`, где `a = 0.10…0.85`, а `r1 = r0·√(N/M_p)`. Тело меньше своего поля (электрон) светит слабее во столько раз, во сколько его поле на поверхности меньше поля протона на `r0`.
- **Цвет — по виду частицы**, как в легенде и в режиме «шар»: протон — оранжевый (`0xFF9650`), нейтрон — светло-серый (`0xC8CDD7`), электрон — голубой (`0x50E6FF`), полюса диполя — красноватый и синеватый (`0xFF5A78`, `0x7A8CFF`). Поэтому p, n и e видны по отдельности: массы протона и нейтрона отличаются на 0,16 %, и шкала «по массе» их бы не разделила. «Нагрев» `h` — сглаженное `|Δv/Δt|` — цвет не меняет: он растит ореол в `1 + 0.45·h` раза и яркость по `0.14 + 0.22·h + 0.15·mm`.
- **Сложение.** Ореол и точка складываются «свет к свету» и мягко насыщаются до `ScenePanel.CLOUD_CAP = 0.95` — тем же приёмом, что слой «поле»: сотни тел дают дымку, но не белый кадр. Рисует один код (`SoftLayer`), поэтому при шейдерах и без них картинка одна и та же; шейдеры в этом режиме рисуют только следы.
- Облака рисуются при любом числе тел — ограничение в 500 снято; на очень больших сценах кадр просто тяжелее.
- **Скорость.** Облака считаются на процессоре (мягкий слой в ¼ разрешения), даже когда тела и следы рисует видеокарта: при 300 телах кадр ~50 мс против ~25–30 мс в режиме шаров. На атоме и песочнице из десятка частиц разницы почти нет; для больших сцен режим и не нужен — там шары.
- Это только рисование: физика, шаг и энергия не меняются. Размер ореола и рост `1 + 0.45·h` — из `indexGPU.html` (проект BGP-agent); отличие — ореол и точка строятся из `Q·N`, а цвет берётся по виду частицы, а не по «нагреву». Тест `CloudTest` (в `build.ps1`) проверяет, что центр ярче ореола, p/n/e разного цвета, размер растёт с массой, в плотной сцене нет насыщения и что при 501 теле облака и слой поля всё ещё рисуются.

### Большие сцены

Чтобы кадр не тратил время на то, чего при тысячах тел не разглядеть:

- полная энергия (для `ΔE/E`) пересчитывается каждый кадр до 500 тел, дальше — раз в 0.25 с и при каждом добавлении или удалении (`App.ENERGY_EACH_FRAME`);
- след пишется у первых 200 тел (`Formula.TRAIL_BODIES`) и у **всех электронов** — даже если они дальше 200-го места;
- облака частиц («частицы: поле») и слой поля рисуются при любом числе тел;
- в Java2D от 400 тел частицы — плоские диски без бликов и теней (`ScenePanel.LARGE`; шейдеры рисуют объём у всех), мелкие (до 3 пикселей) пишутся прямо в пиксели одной картинки (`drawDots`), следы — тонкими линиями без сглаживания; подписи — до 100 тел, стрелки сил — до 500 (`LABELS_MAX`, `FORCES_MAX`). При 10 000 тел рисование кадра ускорилось с ~50–70 до ~12 мс;
- «сколько за нажатие: по 1 / по 10 / по 100» — «+» и «−» добавляют или убирают сразу столько частиц, каждую выбранным способом.

Что упрощено сейчас, пишется в сводке. Физика от этого не меняется.

## 2. Атомные единицы

- `m_p = 1836`, `m_n = 1839`, `m_e = 1` — калибровочные значения; в модели масса вычисляется: `m = N = V·q`;
- плотность одна для всех тел: `q = 2.39·10⁵` (калибрована по `N(e) = 1`); радиус — из `N = V·q`: `rad_e = 0.01`, `rad_p ≈ rad_n ≈ 0.1225`; `S = πr²`, `h = 4r/3`, `V = hS`;
- `r0 = 1` — радиус орбиты электрона вокруг p+n; `rn = 0.45` — радиус орбиты нейтрона;
- `G = 2.4·10⁻⁴³` — реальная гравитационная постоянная в атомных единицах (пресет «честный»); старт и «перезагрузить» ставят «демо» `G = 10⁻⁵`, чтобы движение было заметно;
- частицы рисуются в масштабе объёма: экранный радиус `rad·focal/z`; поле-свечение по умолчанию выключено (клавиша `G`);
- нейтрон входит в атом по умолчанию: каждый атом — дейтерий `p + n + e`, нейтрон на гравитационной орбите `rn = 0.45`; сильного взаимодействия нет;
- старт: **песочница** (пустая сцена), тяготение — **комплексное (КУО)**, `G` — «демо»; частицы добавляются темой «Частицы», атом — кнопкой «+ атом».
- колесом можно приблизиться до `camR = 0.8`.

Шаг — по динамическому времени (см. §1), до 400 подшагов за кадр.

Повторный клик по теме, клик по сцене (без перетаскивания) или `Esc` её закрывают. Если панель не помещается по высоте, она прокручивается. **Правый клик по сцене** открывает меню: сверху «создать здесь: x · y · z» — `протон`, `нейтрон`, `электрон`, `своя` (с текущей массой `m_e`), `атом` (выбранного вида), `диполь` и `рандом` (случайная из них); частица встаёт ровно в точку под курсором, с нулевой скоростью (внутри замкнутой области — не дальше `0.8·R`). Пока правую кнопку держат и ведут, в сцене видна метка-прицел: кольцо, перекрестие и пунктир до пола — по ней и по координатам в заголовке меню видно, куда именно встанет частица. Ниже идут разделы справочника.

Что делают элементы управления:

- **Выбор атома** — первая строка темы «Частицы» и видна всегда: какой атом ставит кнопка «+ атом». Список: водород-1, дейтерий (по умолчанию), тритий, гелий-4, литий-7.
- **Сцена** — одна: песочница (переключателя режима нет). При запуске и после «перезагрузить» она пустая, камера ближе (`camR = 2.5`). Рядом с выбором атома — «перезагрузить».
- **Частицы** — строки «протон p», «нейтрон n», «электрон e», «атом» с кнопками `−` / `+` и счётчиком; «св N» — сколько из них свободных:
  - `+ p` / `+ e` — свободная частица на круговой орбите вокруг всех уже имеющихся тел (как одного тела в их центре масс; скорость из той же формулы, суммарный импульс не меняется), в пустой сцене — в покое; `−` убирает последнюю свободную (кнопка неактивна, если свободных нет);
  - `+ n` — нейтрон на орбиту `rn·(1+0.35k)` вокруг ядра атома (сначала — атом без нейтрона), `−` убирает последний нейтрон;
  - `+ атом` — дейтерий `p + n + e` рядом с центром масс, `−` удаляет последний атом целиком; атомов может не остаться;
  - p, n, e, атом, диполь и своя частица добавляются по одной: первая частица в покое, каждая следующая — на круговую орбиту вокруг уже имеющихся.

### Своя частица (добавка модели)

Строка «своя» и поле **«масса своей, m_e»** в теме «Частицы»: масса задаётся в массах электрона (по умолчанию `1` — как электрон), `N = m`, радиус — из `N = V·q` (`Formula.radOf`), то есть **∝ ∛m**: масса 8 — вдвое больше электрона, 1836 — как протон (под полем показан радиус в `a₀` и в долях радиусов электрона и протона). Цвет — сиреневатый (`0xB6A6FF`), подпись `m`. «+» сначала забирает массу из поля, потом ставит частицу выбранным способом: лёгкая (m < 10) — на 0.8–2.2 от центра масс, тяжёлая — на 1.5–3, как протон. «−» убирает последнюю свою. `World.customMass`, `addCustom`, `removeCustom`; ускорение частицы от её собственной массы не зависит — как и у остальных тел.
- **Постоянная G** — ползунок `log10 G` от `−45` до `6` и пресеты «честный» (`2.4·10⁻⁴³`), «демо» (`10⁻⁵`, по умолчанию), «1».
- **Пауза и сброс** — справа на полосе тем. **Поле** и **след** — в теме «Вид» (клавиши `G` и `T`; след по умолчанию включён). У каждого тела свой цвет следа (оттенки по золотому углу, чтобы соседние тела не были похожи); сами частицы по-прежнему окрашены по виду. Он строится по последним 2250 положениям, по одному на шаг интегрирования (было 375, затем 1125). Яркость падает линейно с возрастом точки, `0.35·(1 − возраст/2250)`, то есть след гаснет вдвое медленнее, чем при 1125. След пишется и когда скрыт, поэтому при включении сразу виден целиком. Рисуется полосами по 24 уровням яркости — одна обводка на полосу, а не на каждый отрезок; «? подсказки» — управление замкнутой областью и границы модели.

### Замкнутая область (замкнутая упругая сфера)

Включается кнопкой «замкнутая область» в теме «Вид» (раздел «стенка»). Под ней ползунки: радиус покоя `R₀` (0.3–10; по умолчанию 1.5), заряд стенки `N` (10¹–10⁶, по умолчанию 10³) и упругость `κ` (10⁰–10⁶, по умолчанию 10⁴). Центр замкнутой области — центр масс сцены в момент включения или сброса. Новые тела кладутся не дальше `0.8·R` от центра.

Стенка работает **через ту же формулу**:

- стенка — источник с зарядом `N`, действие которого взято со знаком −1 (отталкивание; в монографии `f(α)` — множитель проекции частных воздействий на ось, а не знак, поэтому знак стенки задан отдельно — `WALL_SIGN`). На тело на расстоянии `d` до стенки действует `W = Q(d)·N`, направленное от стенки. Вплотную к стенке сила очень большая;
- при `d < δ = 0.02` действует тот же внутренний закон, что у тел: `N(d) = N·(d/δ)³`, поэтому сингулярности нет;
- стенка действует **только изнутри** (`d > 0`). Тело, которое пробило её на большой скорости, дальше летит свободно и стенку не толкает;
- энергия тела у стенки `U = −WALL_SIGN·kQ·N_i·N·φ(max(d, 0), δ)` — та же `φ`, что для пар тел; снаружи это константа `φ(0)`, непрерывно продолжающая внутреннюю.

**Упругость.** Радиус `R` — отдельная степень свободы:

- инерция `m = k_v·N`;
- пружина к `R₀`: `½K(R−R₀)²`, жёсткость `K = kQ·N·κ`;
- **затухание радиуса** `ζ` (по умолчанию 1 — критическое): растянутая стенка возвращается к `R₀` спокойно, без колебаний и без жёсткого упора. Скорость радиуса гасится как `e^(−2ζω·t)`, где `ω = √(K/m) = √(kQ·κ)`;
- реакция тел (давление) растягивает стенку, пружина возвращает её к `R₀`.

**Вязкий слой у стенки.** В слое толщиной `h = (h/R)·R` (по умолчанию 0.2·R) тело тормозится относительно стенки. Скорость к стенке гасится с темпом `γ = вязкость·ω·(1 − d/h)²` — чем ближе к стенке, тем сильнее. Сила торможения передаётся стенке, импульс пары сохраняется, поэтому тело толкает стенку и растягивает её. Отталкивание `Q(d)·N` остаётся как было.

Все тела слоя гасятся **одновременно** (`Chamber.damp`). Раньше тела шли по очереди: каждое меняло скорость центра, которую видело следующее, и итог зависел от порядка тел в списке. Теперь схема неявная. Импульс пары «тело — стенка» за шаг равен `κ_i·u_i′`, где `κ_i = μ_i·(e^{γ_i·dt} − 1)`, `μ_i = m_i·m/(m_i + m)`, а `u_i′` — скорость тела к стенке после шага. Новая скорость центра — из системы 3×3:

`(m·I + Σ α_i n̂_i n̂_iᵀ)·v_c′ = m·v_c + Σ α_i·(v_i·n̂_i − W_i)·n̂_i`,  `α_i = κ_i·m_i/(m_i + κ_i)`,

затем каждое тело — по `v_c′`. С одним телом это ровно прежнее `u′ = u·e^{−γ·dt}`. Импульс тел вместе со стенкой сохраняется точно (тест 30). Потери — точная убыль кинетической энергии. При неподвижных узлах они только растут. Затухание идёт относительно скорости узлов, а импульс уходит только в центр, поэтому при движущихся узлах потери за шаг бывают и отрицательными. Так было и прежде. В среднем подшаге Йошиды `dt < 0` и `κ < 0` — формулы те же.

Вязкость и затухание — **добавка модели, не формулы**. Энергия уходит в «потери» стенки. Они считаются точно (`½μ(u² − u′²)` для тела и `½m(Ṙ² − Ṙ′²)` для радиуса), и сводка показывает их и `ΔE/E` для `E + потери`, так что баланс энергии остаётся проверяемым.

Ползунки замкнутой области: `R₀`, `N`, `κ`, «вязкий слой h / R» (0.02–0.5), «вязкость» (10⁰–10³, по умолчанию 30), «затухание ζ» (0–2). При `ζ = 0` и вязкости, близкой к нулю, замкнутая область снова сохраняет энергию.

История:
1. Сначала пружина работала в обе стороны, а стенка толкала тела с обеих сторон. Быстрый протон (`v = 2`) пробивал стенку, давил на неё снаружи, и через 11 с `R` уходил в минус. Рисование падало с ошибкой `createRadialGradient: r0 < 0`.
2. Логарифмическая пружина не давала `R` уйти в минус, но после сильного растяжения стенка сжималась почти до нуля.
3. Жёсткий упор в `R₀` был признан слишком жёстким.

Теперь торможение вязкое, а возврат — с затуханием. Рисование вырожденной сферы дополнительно пропускается, а `R` страхуется снизу на `0.05·R₀`.

**Радиус покоя.** Пружина узлов тянет к собственному размеру `R₀`, тела давят изнутри (`bodyPush` — суммарная радиальная сила тел на стенку), внешнее давление `p` сжимает снаружи (сила `p·4πR_k²/M` на узел, энергия `p·V`). Радиус покоя — решение `K·(R − R₀) = bodyPush − p·4πR²` (`Chamber.restRadius()`); он и рисуется пунктиром. Жёсткость `K = m·κ`, собственная частота `√κ` — от `G` не зависит: при любом `G` стенка за секунды приходит к радиусу покоя (раньше `K ∝ G`, и при «честном» `G` стенка не двигалась). Ползунки: «упругость κ» (`10⁻²…10³` 1/с², по умолчанию 1) и «внешнее давление» (`10⁻²…10³`, крайнее левое — 0).

**Экстремальная область.** Кнопка «экстремальная» (`Chamber.extreme()`): `N = 10⁹`, `κ = 10`, `τ = 1`. Аналог сверхсильных полей (магнетары, `B ≳ B₀ ≈ 2.35·10⁵ Тл`) только по силе воздействия, без электричества и магнетизма: давление стенки на электрон атома в центре (`R₀ = 5`) — `N/(d²·N_ядра) ≈ 1.7·10⁴` от притяжения ядра; при `N = 10³` — `0.017`. Отношение показывает оверлей (`Chamber.pushRatio`). Оговорка: по `W = Q·N` однородная оболочка внутри даёт ноль (теорема об оболочке); стенка модели давит от ближайшей точки — это правило замкнутой области, и именно оно сжимает вещество. У центра замкнутой области сила стенки меняет направление скачком, поэтому шаг ограничен временем пролёта центральной зоны `√(ρ/a_стенки)`; при `N = 10⁹` баланс `E + потери` держится до `~4·10⁻⁴` за 10 с, расчёт идёт в реальном времени. Выше `10¹⁰` расчёт отстаёт — ползунок `N` ограничен `10¹⁰`.

Замкнутой области в монографии нет — это добавка модели целиком: знак отталкивания стенки, отсчёт `d` до стенки, узлы, пружины, натяжение, вязкость и затухание. Сейчас стенка — 162 узла с динамической формой, центр замкнутой области свободен, и импульс тел вместе с замкнутой областью сохраняется.

Внизу — **описание частиц**: по карточке на протон, нейтрон и электрон. В карточке:

- название и символ, кем и когда открыта;
- `N`, масса в МэВ (938.2 / 939.7 / 0.511) и радиус из `N = V·q`;
- электрический заряд (только подпись, кулона нет);
- роль в модели;
- «в сцене N» — сколько таких тел сейчас.

Значения берутся из тех же констант, что и в динамике. Частицы, которых нет в сцене, приглушены. Панель сворачивается щелчком по заголовку.

Слева — сводка: состав, `A`, `Z`, число тел, `E`, `ΔE/E` от последнего изменения состава или `G`, время. «формула и N = V·q» раскрывает подробности по щелчку.

Клавиши: `Space` — пауза, `R` — сброс, `G` — поле, `T` — след, `WASD`/`Q`/`E` — камера.

## 5. Границы модели

- При честном `G` поле невидимо (`a_G ≈ 10⁻⁴⁰`) — это правильный результат, а не баг.
- Кулона нет: электрон удерживается только гравитацией; химии и `H₂` в модели нет.
- Нейтрон держится только гравитацией. При честном `G` орбита невидима, при демо `G` (и сбросе `R`) — видна; сильного взаимодействия нет, это не ядро.
- Внутреннего строения нуклонов нет: протон и нейтрон — однородные шары (кварки убраны как недоказанные напрямую, см. §1).
- Кора нет: тела проходят друг сквозь друга, внутри шара поле линейно спадает к нулю.
- Пары внутри шара считаются как «точка в однородном шаре радиуса `max(rad_i, rad_j)`» — для перекрытия двух сфер это приближение.

## 6. Известные ограничения

- С замкнутой областью энергия тел не сохраняется: часть уходит в вязкость слоя и затухание радиуса. Проверяется баланс `E + потери`. Очень быстрые тела (`v ≳ 3` при «демо») могут прорваться сквозь слой; помогает больше вязкости или больше `N`.
- Замкнутая область отталкивает по ближайшей точке стенки, поэтому её поле есть во всём объёме (у центра `kQ·N/R²`). При малом `R₀` и большом `N` это заметно влияет на движение внутри. Вплотную к стенке поле очень сильное.
- Поле считается за `O(N²)`.
- Несколько нейтронов могут перекрываться.
- При больших `G` шаг становится мелким; если 400 подшагов за кадр не хватает, время замедляется.
- Новый атом (`+ атом`) запускается с нулевым импульсом относительно мира, но в поле уже существующих атомов — орбиты не строго круговые.
- Физику можно проверять без окна: `World` открывает `accelerate`, `step`, `energy`, `dynTime`, `reset`, `advance` (см. `FormulaTest`).
- Аддитивное смешивание свечения поля (`'lighter'` в canvas) в Java2D не повторено: свечение накладывается обычным смешиванием.
